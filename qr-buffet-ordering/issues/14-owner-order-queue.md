# 14: คิวออเดอร์ของเจ้าของร้าน: กรอง สถานะ และยกเลิกพร้อมเหตุผล

Status: ready-for-agent

Source: `../spec.md` (user stories 55, 56, 58) และ `../plan.md` (Step 7, Step 14 (`/owner/orders`)); ถ้า spec กับ plan ขัดกัน ให้ยึด spec; หน้าจอที่ออกแบบแล้ว: frame o08 ใน `../../design/out/`

## What to build

เจ้าของร้านเปิดหน้าออเดอร์เห็นออเดอร์ของวันนี้เป็นการ์ดคิว กรองตามสถานะ (รอรับ/กำลังทำ/พร้อมเสิร์ฟ) เห็นจำนวนต่อสถานะและจำนวนที่ล่าช้าเกินกำหนด ยกเลิกออเดอร์พร้อมเหตุผลได้เหมือนครัว กดเริ่มทำ/พร้อมเสิร์ฟได้ด้วยบัญชีเจ้าของร้าน และดูจอครัวด้วยบัญชีตัวเองได้ ส่วนรายการ "เสร็จแล้ววันนี้" แสดงออเดอร์ที่พร้อมเสิร์ฟ/ยกเลิก

## Blocked by

12 ครัวเลื่อนสถานะ เริ่มทำ/พร้อมเสิร์ฟ และยกเลิกพร้อมเหตุผล

## Acceptance criteria

- [ ] หน้าออเดอร์ตรงกับ mockup o08 (การ์ดคิว ปุ่มสถานะเดียวต่อการ์ด การ์ดใหม่สี alert); ปุ่ม แก้ไข/ย้ายโต๊ะ/รวมบิล บนการ์ดทำงานใน ticket 17/21/22 ตามลำดับ — ใน ticket นี้ไม่แสดงปุ่มเหล่านั้นจนกว่า ticket นั้นจะเสร็จ
- [ ] Owner ยกเลิกออเดอร์พร้อมเหตุผลสำเร็จด้วยกฎเดียวกับครัว (ใช้บริการร่วม) และ Kitchen ไม่เห็นเส้นทางของ owner
- [ ] รายการและตัวนับอัปเดตเองผ่าน hub (ไม่รีเฟรช)
- [ ] สร้างครบทุกชั้นที่ slice นี้แตะ (schema/API/UI) พร้อมเทสต์ seam 1 ตามหัวข้อ Testing Decisions ของ spec และ smoke run บน stack จริง (`docker compose up`) ที่เห็นพฤติกรรมของ ticket นี้ด้วยตา; โมเดลที่เพิ่มเข้า migration `Initial` ตัวเดียว (ดู ticket 01)
